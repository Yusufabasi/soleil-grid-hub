# ADR-0020: SQL-first schema with unmanaged Django models

**Date**: 2026-10-24
**Status**: accepted
**Deciders**: tech lead, database engineer, software architect

## Context

The schema uses features Django migrations do not model: partitioned tables, deferred constraint triggers,
`SECURITY DEFINER` functions, row-level security, per-role privileges and `ENABLE ALWAYS` triggers. It is
tested directly in PostgreSQL (invariant tests, concurrent double-credit test). Django's migration
autodetector would lose or fight these objects.

## Decision

`db/schema.sql` plus numbered SQL migrations (expand, then contract) are the authority. Every Django model
is `managed = False` and maps to a table in the `hub` schema. Django migration files only contain `RunSQL`
operations that apply the numbered SQL files in order, so `manage.py migrate` stays the single deployment
command. A test compares the models with the introspected database. The ledger is written only through the
definer function. Each deployable has its own settings module and database role; `search_path` is a role
setting. Bulk and partitioned inserts use raw SQL or `COPY` via psycopg 3.

## Alternatives Considered

### Django-managed models with migrations and RunSQL for the extras
- **Pros**: the autodetector handles ordinary tables and indexes.
- **Cons**: two sources of truth for the schema; triggers, partitions and grants live in migrations the invariants test cannot load as one file.
- **Why not**: the invariants must be provable in one executable schema file.

### Generate the SQL file from models
- **Pros**: one source in Python.
- **Cons**: cannot express most of the controls.
- **Why not**: not feasible.

## Consequences

### Positive
- The tested schema is exactly what production runs; the alignment tests keep the API and schema in step.

### Negative
- No autogenerated migrations; every change is hand-written SQL with a reviewed expand and contract plan.
- Model fields must be kept in step with columns by hand; the introspection test catches drift.

### Risks
- A developer adds a managed model by habit; the introspection test and a lint rule reject it.
