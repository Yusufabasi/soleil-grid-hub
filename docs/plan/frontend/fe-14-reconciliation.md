# Frontend slice 14: Reconciliation (statements, batches, exception queue, resolution proposals)

- **Goal:** finance officers upload provider statements, follow matching progress, work an exception queue, request system evidence from the provider, and (as finance leads) propose resolutions that become approvals; no money is posted from this screen, and the screens say so.
- **Depends on:** backend slice 14 (reconciliation); frontend slices fe-00, fe-01 (step-up, approval helper), fe-03 (money display, ledger links); the checker side is fe-15.
- **Requirements served:** FR-14, FR-04 (resolution postings through approval), FR-16, NFR-10, NFR-11.
- **Size:** M, 5 days.
- **Spikes or open items:** the posting that a resolution will create is generated by the server and is not part of any response before approval, so the screen cannot preview debit and credit lines (as `docs/08` 3.7 wanted); default: describe the effect in words per resolution type and show the real lines after approval through the ledger link **[open: ask backend slice 14 whether `ReconException` can carry a `proposed_posting`]**.

## Global constraints

- Server Actions banned; no secrets in `NEXT_PUBLIC_*`; image optimiser off; nonce CSP on every page.
- Access token in memory only. Reconciliation screens are `finance_officer` only; the administrator and others have no entry.
- Budgets: staff first load at most 250 KB; the upload form reads no file contents in the browser (no CSV parser shipped).
- next-intl `/fr` and `/en`; French first.
- WCAG 2.2 AA: native tables, status as text, progress as `<progress>` with label, file input with label and visible file name.
- Generated client only. Statement upload uses `multipart/form-data` with an `Idempotency-Key` and sends only the file, provider and the two dates.
- Every resolution is a proposal (HTTP 202 approval, exception moves to `pending_approval`); the UI never says "resolved" until the exception status from the API is `resolved` or `written_off`.
- Resolution controls require role `finance_officer` and attribute `finance_lead` (`x-requires-attribute` on `resolveReconException`); statement upload and evidence requests need only the role.
- `match_to_top_up` requires system evidence (`evidence_id`); an uploaded file alone is never enough and the form cannot be submitted without selecting evidence.
- No optimistic updates on this slice; money amounts shown with `exact: true`.
- Cell content from statements is untrusted text (shown inert; the server already neutralises formula-leading cells).
- Do not edit frozen files.

## Review focus

1. Re-uploading the same file creates a second batch or shows a vague error: `StatementUpload.test.tsx` "409 statement_already_imported shows plain message and no new batch" (Task FE-14.1).
2. A resolution looks applied while the approval is pending: `ResolutionForm.test.tsx` "202 sets pending approval notice; status chip stays Pending approval" (Task FE-14.4).
3. `match_to_top_up` is submitted with only an uploaded file or without evidence: `ResolutionForm.test.tsx` "evidence required for match_to_top_up" (Task FE-14.4).
4. A conflict-of-interest or self-approval refusal is not understandable: `errors.test.ts` mapping `conflict_of_interest` (Task FE-14.4).
5. A huge file is sent and the user waits blind: `StatementUpload.test.tsx` "over 10 MB rejected before upload; progress and matching status shown" (Task FE-14.1).

## Demo script

1. Sign in as a finance officer; open `/fr/staff/reconciliation`: "Rapprochement", upload form "Importer un relevé de l'opérateur". EN: "Reconciliation", "Import a provider statement".
2. Import the stub statement: "Relevé reçu. Le rapprochement est en cours." then "{n} lignes rapprochées sur {m}".
3. Import the same file again: "Ce relevé a déjà été importé. Rien n'a été ajouté." / "This statement was already imported. Nothing was added."
4. Open `/fr/staff/reconciliation/exceptions`: "File des exceptions" with a "Dans le relevé seulement" item; open it.
5. Press "Demander une preuve à l'opérateur" / "Request evidence from the provider": the evidence appears after the pull.
6. As a finance lead choose "Rattacher à une recharge" / "Match to a top-up", pick the evidence, write the note, submit: "Proposition n° … soumise. Rien n'est encore enregistré." / "Proposal no. … submitted. Nothing has been posted yet." The status shows "En attente d'approbation" / "Pending approval".
7. As a finance officer without the finance lead attribute: "Seul un responsable financier peut proposer une résolution."
